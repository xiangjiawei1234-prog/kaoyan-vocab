# 性能测量（提示词 14 · 批次 C）

- 日期：2026-10-22
- 执行：impl-visual（批次 C：09 纸感视觉 + 14 性能测量与小步整理）
- 环境：macOS（本机）· Google Chrome 155.0.8059.85 · `--headless=new` · Node v26.7.0 · 本地静态服务 `127.0.0.1` + 随机端口 · 每次运行全新 `--user-data-dir`
- 结论口径：**pre-c（批次 A/B 完成后的工作区）→ after（批次 C 完成后）为主**；pre-A（批次 A 开始前的冻结快照）仅作历史参考，避免把批次 A/B 的改动算到本批。

## 1. 方法与工具

驱动与脚本都在 `tests/reports/qa/`（gitignore，不入库），复用 QA 已建立的 CDP 驱动（Node 内置模块 + 全局 WebSocket，无第三方包）：

| 口径 | 脚本 | 说明 |
|---|---|---|
| 冷启动 / longtask / heap / SW 受控 reload / 断网 reload / 切书 / 范围筛选 / 列表搜索 | `perf-14-baseline.mjs`（QA 编写，同脚本改 label 复跑） | 首次导航用 no-store 静态服务；冷启动重复 3 次取 median；首卡 `README` 探针记录「进 DOM / 可交互」的 `performance.now()`；longtask 用 `PerformanceObserver({type:"longtask", buffered:true})`；heap 用 `HeapProfiler.collectGarbage` + `Runtime.getHeapUsage` |
| 交互同步耗时 / file:// 双击模式 / CSS rule usage | `perf-14-extra.mjs`（本批新增，工作区 gitignore） | 页面内 `performance.now()` 包住同步调用（不含 CDP 往返与下一帧布局）；file:// 用同一探针单独导航；CSS 用 `CSS.startRuleUsageTracking` 遍历视图后统计 |

产物：`perf-14-baseline.json`（pre-A）、`perf-14-pre-c.json`、`perf-14-after.json` / `perf-14-after2.json` / `perf-14-after3.json`、`perf-14-extra.json`，以及 `results/` 下逐项记录与 `shots/perf-*.png`。

## 2. 主口径：冷启动与交互延迟

冷启动为「全新 profile 首次导航 → 首卡可交互」，3 次重复取 median（单位 ms；资源 9 个、约 9.6MB 未压缩词库同步交付，未改动）。

| 指标 | pre-A 基线（历史参考） | pre-c（post-A/B，本批前） | after（post-C，本批后，3 次 median） | 变化（pre-c→after） |
|---|---|---|---|---|
| DOMContentLoaded | 90.1 | 90.1（86.3–98.7） | 88.5（86.4–90.2） | −1.6ms，噪声内 |
| 首卡进 DOM | 88.8 | 87.9（83.9–95.8） | 86.0（84.1–87.7） | −1.9ms，噪声内 |
| 首卡可交互 | 89.4 | 89.5（85.6–97.6） | 87.7（85.6–89.3） | −1.8ms，噪声内 |
| 首屏可操作（含探针口径 appReady） | 99 | 98（95–116） | 96（93–100） | −2ms，噪声内 |
| 主线程 longtask（>50ms） | 0 | 0 / 0 / 0 | 0 / 0 / 0 | 无 |
| GC 后 JS heap | 10.28MB | 10.46MB | 10.44MB | −约 19KB |

- 预热与离线口径（单次采样，注意本机波动）：SW 受控 reload 的 DCL：pre-A 57.1 → pre-c 60.2 → after 67.7（3 次 56.8/67.7/69.2，run-to-run 波动约 12ms）；断网 reload DCL：60.8 → 59.6 → 68.0（65.1–68.4）。after 的预热/离线单次值偏高但落在观测波动范围内，且冷启动主指标与 heap 未退化；不作为“已确认性能回归”。
- 首次切书（考研→四级）与热切换：pre-A 10.3 / 12.6 / 13.6 / 9.7；pre-c 10.4 / 12.5 / 12.9 / 10.6；after 11.4 / 14.5 / 12.8 / 10.3（ms，真实点击 → 新书标题/范围/首卡落定）。差异在噪声内。
- 范围筛选（pmin 步进真实点击）：pre-A 6.2 / 6.1；pre-c 7.4 / 7.2；after 7.8 / 7.5。
- 词表搜索（真实输入 `abandon` / `contr` / `考研`）：pre-A 1.6 / 1.3 / 6.9；pre-c 1.4 / 1.2 / 4.0；after 1.6 / 1.4 / 7.0。
- 所有阶段 console error = 0。

## 3. 补充口径（perf-14-extra，after 工作区）

用内存中的合成历史（约 1,800 条学习记录、67 个熟练词、14 天学习记录）测量同步操作耗时（ms，页面内 `performance.now()`，中位数）：

| 操作 | median | 说明 |
|---|---|---|
| `startSession("main")` | 2.2 | 含构建队列/冻结范围，不含下一帧渲染 |
| 判定「会」→ 释义渲染 | 4.9 | 含 SRS 写进度 + save + renderCard |
| 切到统计页 `show("stats")` | 2.6 | 含全部图表重算与 innerHTML |
| 切到背诵页 `show("study")` | 0.6 | |
| `inScopeCount()`（7,997 词） | 0.1 | 单次全量扫描已足够快 |
| `buildQueue()` | 0.3 | |
| `dueForecast(14)` / `frequencyMastery()` | 0.2 / 0.3 | |
| 列表搜索输入事件（含 7,997 词过滤 + 重绘） | 0.8 | |
| 切书（同步调用） | 11.8 / 11.1 | 换 W/读取记录/重渲染，属预期成本 |
| 精确 heap（上述合成数据 + 统计页/列表交互后） | 11.24MB | GC 后 |

- file:// 双击模式（无 Service Worker；与静态服务 / 离线缓存口径区分）：首卡进 DOM 72.4ms、可交互 73.1ms、DCL 74.4ms，longtask 0；`navigator.serviceWorker.controller=false`（符合直接双击打开时缓存不可用的说明）。
- CSS rule usage：`css/app.css` 共 968 条规则；单次遍历（背诵 recall/揭示/改判 + 词表搜索 + 统计全部 details 展开 + 设置页 + 深色）匹配到 662 条（68.4%）。未匹配部分包含只在其他断点、hover/focus、减少动效、打印等状态生效的规则，**不能直接当作死规则删除**；本次只按“静态可证无引用”删除死规则（见 §4），未做大规模 CSS 重写。

## 4. 本批的“有证据的小步整理”

没有发现需要优化的主线程热点：在 7,997–12,083 词规模下，全量扫描类操作均 ≤0.3ms、统计页整页渲染 2.6ms、冷启动 longtask 始终为 0；因此**没有为了改动而改动调度/渲染逻辑**（如把 `renderStats` 多次扫描合并，经测量收益 < 1ms，不做）。本批实际整理：

1. 删除 `#curveInfo` legacy 兜底渲染分支（节点早已删除，原路径安全 no-op；设计文档 §6 遗留观察第 3 条指派本批清理）。行为等价由既有 `test-rhythm` 与新增静态断言覆盖。
2. CSS 收敛（均为静态可证无引用/重复覆盖）：
   - 删除无引用的 `.list-actions` 规则与窄屏副本（HTML/JS 中 0 处引用）；
   - 删除被 `#v-set { max-width: 1120px }` 覆盖的重复 `#v-set { max-width: 820px }`；
   - 删除空的分区注释；
   - 把 3 处无效的嵌套 `:has`（`CSS.supports("selector(.a:has(.b:has(.c)))")` 在 Chrome 155 实测为 false）改写为等价的扁平选择器——这是完成页行数补偿此前一直未生效、导致 A-40 布局缺陷的根因之一。
3. 小等价整理：`renderCard` 入场动画计时器 240ms→200ms（动画已收敛到 160ms）；`bindSet` 删除重复的 `updateSettingsSummary()` 调用（`updateScopeCount` 内已调用）。
4. 未新增任何数据缓存：现有 `posMaskCache` / `exFormIndexCache` 均按「当前词书 words 引用 + bookId」失效，切书重建；范围筛选、学习状态、熟练变化不改变词性掩码/词形索引，不会读到过期结果。09 新增的范围摘要只读 08 的 `sessionPlan.scopeSig`/当前设置，不缓存派生统计。
5. `js/test-perf-guards.mjs`：没有新增空测试。清理后的等价性已由新增的 `js/test-app.mjs` 第 19 节（25 条断言：无嵌套 `:has`、无 `#curveInfo`/`ring-chip` 残留、details 结构、范围摘要冻结/跳转、特训折叠、survey 样本量）+ 既有 test-rhythm/test-lifecycle 覆盖；本批测量也证明没有值得长期守护的性能逻辑（无新缓存/无新扫描路径），故按任务约定写明理由而不加空文件。

## 5. 结论

- 批次 C 的 09 视觉改动（首屏统计条合并、上下文条、统计页 details、动效 120–180ms）**没有引入可测量的启动/渲染退化**：冷启动 median 88.5ms（pre-c 90.1ms）、首卡可交互 87.7ms（pre-c 89.5ms）、longtask 0、heap 略降；切书/筛选/搜索差异在 run-to-run 噪声内。
- 交互同步耗时全部在个位数毫秒内，未发现 14 所述“重复转换/扫描/重绘”热点；因此保留同步词库交付、完整预缓存与直接双击能力，不引入框架/联网懒加载/构建步骤。
- 本批只做低风险等价整理与 CSS 死规则收敛；有收益的优化若未来出现，应以本文件的脚本/口径复测后再动。

## 6. 未测边界

- 真机（iOS/Android/Safari/Firefox）、低端设备、真实网络与 OS 冷缓存、读屏与系统语音：未测，不能由本机 headless 数字外推。
- headless Chrome 的布局/计时与真机存在差异；单次预热/离线数字波动较大，本文件已给出多次采样范围。
- CSS rule usage 只覆盖一次“桌面 + 已列状态”遍历，未覆盖 hover/focus-visible/全部断点/减少动效/打印；不能据此直接删除未匹配规则。
- 内存数字是 JS heap（GC 后），不含 GPU/进程/词库源码外开销。
